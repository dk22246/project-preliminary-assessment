# 海南岛内正式政策卡与校验

## 海南及三亚政策检索来源与顺序

### 政策检索前提

先完成企业研究，并判断企业现有业务中哪些业务、管理职能、贸易活动、投资活动或结算活动适合在海南及三亚开展。

政策必须由拟落地业务触发，不得因为海南存在某项政策而反向虚构企业业务。

## 拟落地业务到政策的一一映射

完成企业研究后，先建立拟落地业务清单，再开始政策检索。每项业务至少写明：

- 企业现有事实基础；
- 拟由三亚主体承接的职能、人员、合同、收入、利润、结算或投资路径；
- 是否可从原生产基地或原经营地分离并在三亚中央商务区实质运营；
- 可形成的税收、贸易、投资、就业、品牌或产业带动；
- 需检索的海南省级、驻琼执行机构和三亚市级主管部门。

制造、矿业、农业等重资产企业优先研判可迁移的总部、贸易、投资、结算、品牌、渠道和供应链管理功能。除非已有产线、用地、物流、环保、能耗和人员等事实依据，不得假设全部生产活动迁入三亚。

每项拟落地业务分别完成政策判断。总部和管理团队迁入，检索总部认定、企业所得税和人才个人所得税；国际贸易和海外销售，检索EF账户、跨境人民币和外贸政策；境外投资，检索ODI及境外投资所得政策；进口加工，检索零关税和加工增值政策；文旅、体育、科技、工业等活动，检索对应省级和三亚市级主管部门政策。上述示例只由真实业务触发，不构成固定检索清单。

### 检索顺序

每项政策按以下顺序检索：

1. 正式政策原文；
2. 实施办法或实施细则；
3. 认定办法、操作规程或办理指南；
4. 当前申报通知及兑现要求；
5. 官方政策解读。

先检索海南省级具体主管部门和驻琼执行机构，再检索三亚市级政策。

新闻、规划、行动方案和招商宣传只能用于发现线索，不能替代正式政策依据。

### 政策解释要求

每项匹配政策必须先用一句话说明：

“企业开展什么业务或达到什么条件后，可以获得什么税收优惠、资金支持、办理便利或账户功能。”

不得只复制政策名称，也不得使用“给予扶持”“享受相关优惠”等空泛表述。

## 可进入报告的政策

只将同时满足下列条件的政策写入“政策匹配清单”：

- 地域明确适用于海南省、三亚市或三亚中央商务区；
- 来源为政府、厅局、税务机关、三亚中央商务区等发布的官方原始文件；
- 已核验为正式、现行政策；
- 能写清企业整体迁入后实际承接的业务，以及企业必须完成的实质落地动作。

国家政策只作制度背景或上位依据。外省政策、海南省内非三亚区域专属政策、征求意见稿、拟出台政策、已过期政策及二手解读均不进入报告政策清单。

不要预设税收、人才、贸易等政策类别。总部经济、综合扶持或园区专项等政策均按其**实际名称**独立成卡。

## 政策卡契约

```json
{
  "policies": [
    {
      "name": "政策名称",
      "region": "三亚市",
      "region_evidence": "官方文件中关于适用地域的原文或准确摘要",
      "source_type": "official",
      "source_url": "https://example.gov.cn/policy",
      "status": "current",
      "enterprise_business": "海南主体承接的具体业务、人员或收入",
      "landing_action": "企业需完成的实际落地动作"
    }
  ]
}
```

完整政策卡还应记录发文机关、文号、发布日期/有效期、适用对象、支持内容、办理或兑现方式、企业证据和政策价值。

## 执行门禁

对全部拟写入报告的政策卡运行：

```powershell
& $py 'C:\Users\Administrator\.codex\skills\project-preliminary-assessment\scripts\validate_policy_scope.py' policies.json
```

返回码为 1 时，修正或移除该卡；不得绕过校验。校验通过仅说明卡片具备最低证据字段，不等于企业已经取得认定、批准、备案或兑现资格。

在所有拟写入报告的政策卡通过校验后，复核每项拟落地业务是否已完成对应主管部门检索和政策判断；缺少判断时，补检索或在报告中说明无正式、现行海南岛内政策的原因，之后才可形成 Word 报告。
