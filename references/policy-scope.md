# 海南岛内正式政策卡与校验

## 海南及三亚政策检索来源与顺序

### 政策检索前提

先完成企业研究，并判断企业现有业务中哪些业务、管理职能、贸易活动、投资活动或结算活动适合在海南及三亚开展。

政策必须由拟落地业务触发，不得因为海南存在某项政策而反向虚构企业业务。

## 拟落地业务到政策的一一映射

完成企业研究后，先建立拟落地业务清单，再开始政策检索。每项业务至少写明：

- 企业现有事实基础；
- 拟由三亚主体承接的职能、人员、合同、收入、利润、结算或投资路径；
- 是否可从原生产基地或原经营地分离并在三亚中央商务区实质运营；
- 可形成的税收、贸易、投资、就业、品牌或产业带动；
- 需检索的海南省级、驻琼执行机构和三亚市级主管部门。

每项拟落地业务必须至少形成一条动态检索记录，记录业务编号、检索主题、检索主管部门、结论、正式政策编号（如有）、未纳入或未触发原因、下一步需核实的企业事实。结论仅可使用：

- `direct_match`：已有正式政策和企业业务基础，但资格、认定或办理条件仍须核验；
- `conditional_opportunity`：存在正式政策或办理便利，须以新增主体、业务、人员、合同、资金或投资事实触发；
- `not_triggered`：政策主题存在，但本轮没有企业事实支持其触发；
- `no_current_policy`：已检索对应主管部门，未发现可进入报告的现行正式海南岛内政策。

不得将上述动态台账退化为企业所得税、个税、EF、ODI等固定清单。也不得在事实不足时删去主题；应保留“暂未触发”或“未发现现行政策”的理由。

动态台账是检索完整性的内部控制，不是正式报告的默认展示内容。正式报告按“企业整体在三亚实质落地”的招商情景，只呈现对招商谈判有直接价值的重点政策；不单独设置“待核政策事项”或逐项展示否定结论。资格、认定、申报和办理前提必须保留在重点政策表的“享受前提及三亚承接”列。

制造、矿业、农业等重资产企业优先研判可迁移的总部、贸易、投资、结算、品牌、渠道和供应链管理功能。除非已有产线、用地、物流、环保、能耗和人员等事实依据，不得假设全部生产活动迁入三亚。

每项拟落地业务分别完成政策判断。总部和管理团队迁入，检索总部认定、企业所得税和人才个人所得税；国际贸易和海外销售，检索EF账户、跨境人民币和外贸政策；境外投资，检索ODI及境外投资所得政策；进口加工，检索零关税和加工增值政策；文旅、体育、科技、工业等活动，检索对应省级和三亚市级主管部门政策。上述示例只由真实业务触发，不构成固定检索清单。

### 检索顺序

每项政策按以下顺序检索：

1. 正式政策原文；
2. 实施办法或实施细则；
3. 认定办法、操作规程或办理指南；
4. 当前申报通知及兑现要求；
5. 官方政策解读。

先检索海南省级具体主管部门和驻琼执行机构，再检索三亚市级政策。

新闻、规划、行动方案和招商宣传只能用于发现线索，不能替代正式政策依据。

### 政策解释要求

每项匹配政策必须先用一句话说明：

“企业开展什么业务或达到什么条件后，可以获得什么税收优惠、资金支持、办理便利或账户功能。”

不得只复制政策名称，也不得使用“给予扶持”“享受相关优惠”等空泛表述。

## 可进入报告的政策

只将同时满足下列条件的政策写入“政策匹配清单”：

- 地域明确适用于海南省、三亚市或三亚中央商务区；
- 来源为政府、厅局、税务机关、三亚中央商务区等发布的官方原始文件；
- 已核验为正式、现行政策；
- 能写清企业整体迁入后实际承接的业务，以及企业必须完成的实质落地动作。

国家政策只作制度背景或上位依据。外省政策、海南省内非三亚区域专属政策、征求意见稿、拟出台政策、已过期政策及二手解读均不进入报告政策清单。

不要预设税收、人才、贸易等政策类别。总部经济、综合扶持或园区专项等政策均按其**实际名称**独立成卡。

## 重点政策的报告表达

- 每项重点政策先用企业语言命名，再在下方列出正式文件依据。优先写清利益和工具，例如“企业所得税15%优惠”“高端紧缺人才个人所得税优惠（实际税负15%封顶）”“EF账户（多功能自由贸易账户）”。
- 一项优惠的政策原文、实施细则、认定公告或申报口径合并为一行；不得把同一项人才个税优惠拆成两行。各文件仍须分别保留官方原文链接、文号和 `P` 编号。
- “企业能获得什么”应明确到税率、免征范围、资金便利或账户功能；“享受前提及三亚承接”写清企业在三亚需承接的主体、人员、合同、收入、利润、结算或投资动作。
- 对企业整体落地情景有价值但不构成税收或资金优惠的事项，如EF账户、ODI备案和外汇登记，应明确标注其是办理或资金便利，不得包装成财政补贴。

## 政策卡契约

```json
{
  "policies": [
    {
      "name": "政策名称",
      "region": "三亚市",
      "region_evidence": "官方文件中关于适用地域的原文或准确摘要",
      "source_type": "official",
      "source_url": "https://example.gov.cn/policy",
      "status": "current",
      "enterprise_business": "海南主体承接的具体业务、人员或收入",
      "landing_action": "企业需完成的实际落地动作"
    }
  ]
}
```

完整政策卡必须记录发文机关、文号、发布日期、现行状态依据、适用对象、支持内容、办理或兑现方式、企业证据和政策价值；其 `source_id` 必须一一对应参考资料中的 `P` 类官方原文链接。来源为 `official` 不得仅靠标签声明，原文链接必须为可识别的官方 HTTPS 地址。

## 执行门禁

对全部拟写入报告的政策卡运行：

```powershell
& $py scripts/validate_policy_scope.py policies.json
```

返回码为 1 时，修正或移除该卡；不得绕过校验。校验通过仅说明卡片具备最低证据字段，不等于企业已经取得认定、批准、备案或兑现资格。

在所有拟写入报告的政策卡通过校验后，运行：

```powershell
& $py scripts/validate_business_policy_ledger.py report-data.json
```

该校验要求每项拟落地业务均有完整政策检索结论，并核对政策卡、`P` 类来源和企业业务的关联。两项校验均通过后才可形成同源 HTML/PDF 报告；用户需要可编辑文件时再同步生成 Word。
