# 业务能力发现与候选处置

研究阶段不得直接把企业资料压缩为 3—6 个收入型业务。先在 `enterprise-findings.json` 建立事实和业务能力候选，再由编译器生成后台台账；报告页面继续只展示筛选后的 3—6 项核心业务。

## 事实台账

先读取 `enterprise-findings.json.research.enterprise_profile.research_route`。`listed_disclosure` 以最新年度报告为集中主资料，年报、招股书和交易所公告确定财务、股权与法定业务口径；以前年度报告只定向补充主资料未解决的历史缺口，企业官网、投资者关系及政府或行业协会材料只补当前产品、最近一年重大变化、战略、海外布局、行业位置和风险缺口。`nonlisted_public_evidence` 不进行无依据的交易所或年报检索：第一层只读取企业官网、官方公众号或正式材料中的产品、服务、解决方案和项目页面；第二层只用政府项目/备案/许可、政府采购/招投标及客户或合作方正式公告验证经营事实。工商股权和官方风险记录按各自专项规则处理，不得用媒体报道替代。不可访问来源必须记录原因和替代来源。

每条事实记录企业做了什么、对象、企业角色、活动载体、时间、来源和可信度。先记录事实，不在本层判断政策或三亚落地。

事实候选完成后，再按 `references/policy-opportunity-radar.md` 将事实信号展开为可合理相邻的经营活动。相邻活动必须能由已有产品、渠道、组织、人员、贸易、投资或资金事实解释；不得因为海南存在优惠而新造业务。

## 业务环节穷尽排查（防漏拆）

拆解企业业务时像人一样思考：先回答「这家公司卖什么、怎么做、走哪些渠道」，据此推断完整的业务全景，再逐环节核对，穷尽覆盖，不得遗漏任何实际经营环节。

先回答三个问题：
1. 卖什么：产品、服务、解决方案分别是什么？
2. 怎么做：是否有研发、生产/制造、销售、服务等环节？
3. 走哪些渠道：销售通过哪些渠道触达（线上电商 / 线下实体门店 / 经销批发 / 工程集采 / 直销）？

再按下表逐项核对，凡企业实际存在的环节，必须拆出对应经营活动，不得合并、不得遗漏：

| 环节 | 常见同义表述（必须归一到同一经营活动） |
|---|---|
| 研发/设计 | 研发、设计、技术开发、软件开发 |
| 生产/制造 | 制造、生产、组装、委托加工 |
| 销售—线上电商 | 电商、线上零售、平台店、直播、自建商城、网购 |
| 销售—线下实体 | 门店、实体店、直营店、体验店、加盟、连锁、专柜 |
| 销售—经销/批发 | 经销、分销、代理、批发、渠道商 |
| 销售—工程/集采 | 精装配套、工程渠道、政府采购、集采 |
| 服务/运营 | 安装、售后、维修、运维、平台运营、代运营 |
| 贸易/供应链 | 采购、贸易、供应链、仓储、结算、跨境收付 |
| 投资/金融 | 投资、理财、资金运作、并购、基金 |
| 品牌/IP/内容 | 品牌授权、IP 运营、内容分发、会员 |

同一环节用不同词语形容（如“电商”“线上零售”“网购”）必须归一到同一标准经营活动、做同一目录判断，不得因用词不同而重复拆出或漏掉。一个公司的业务通常只有几类，必须全部 cover 到——宁可多拆一个环节，也不得漏掉一个实际存在的环节；拆解完成后反向自检“这家公司还有哪个环节没被覆盖”。

## 候选池

收入业务、产品解决方案、品牌/IP、赛事会展活动、渠道平台生态、贸易供应链结算、投资总部管理职能均可进入候选池；不要求单独披露收入。主办、承办、重复实施、长期团队/平台、明确合同/交付/运营职责或战略表述任一成立时，应建立候选。

角色按 `operator`、`co_operator`、`commercial_partner`、`one_off_marketing` 判断。单次普通赞助、被动曝光、荣誉公益或无实际经营角色的合作原则上不能直接升级为落地业务。

每个候选必须为 `include`、`merge` 或 `exclude`：纳入/合并时关联有效落地业务；排除时记录证据不足、一次性营销、不可分离或不适合三亚等原因。候选不得静默消失。

## 升级与停止

候选进入正式落地业务，须同时具备事实基础、实际经营角色、重复性、可分离性、三亚承接路径、至少一项实际贡献和合规可行性。上市路由完成一轮集中披露研究、七类能力发现/未发现及全部候选处置后即可结束发现阶段；非上市路由完成企业官方、政府经营记录、客户/合作方正式公告、公开登记、官方风险记录和 `nonlisted_evidence_checks` 全部处置，完成七类能力发现/未发现、一次定向缺口补查且每个候选均有处置后即可结束。

上述停止条件先写入 `enterprise-findings.json.research_stop_gate`；完成企业与政策两份精简输入后运行 `ppa.py compile`，由编译器生成并一次性替换五份正式台账。`source_channels` 必须完成对应披露路由的必查来源处置；主体、核心业务、行业位置、国内外业务、最近三个完整年度财务、股权和风险分别标记为 `completed`、`not_available` 或 `inaccessible`，后二者必须写原因。两条路线均只要求一轮符合各自路径的集中研究或定向补查，不得为凑轮次堆砌重复媒体报道；公开信息仍缺失的字段写“需企业补充”，不得用注册资本、融资额或行业均值推算。`not_available` 表示规定渠道已完成但没有可靠公开数据，不是研究失败。正式校验只由 `ppa.py finalize` 在报告生成前统一执行一次。
