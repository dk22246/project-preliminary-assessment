# 海南自由贸易港鼓励类产业目录匹配模块设计

日期：2026-08-02  
适用 Skill：`project-preliminary-assessment`

## 一、目标

在企业“主要业务及产品拆解”完成后，对企业每一项核心现有业务强制执行海南自由贸易港鼓励类产业目录匹配，并在 HTML、PDF 和按需生成的 Word 报告中固定展示结果。

该模块只回答一个问题：

> 企业已经存在的具体业务、产品或服务，是否与现行海南自由贸易港鼓励类产业目录的具体条目及界定要点相符？

该模块不判断企业是否已经取得主管部门认定，也不在本模块内判断企业所得税 15%、加工增值等具体政策资格。后续政策分析可以引用目录匹配结果，但不得反向影响本模块的业务判断。

## 二、设计原则

1. **所有企业强制分析并展示。** 无论是否发现匹配项，报告都必须出现本模块。
2. **每项核心业务全覆盖。** `businesses` 中的每项业务必须有且只有一条主判断，不能只挑容易匹配的业务。
3. **业务事实优先。** 仅依据企业已公开存在的业务、产品、服务和经营活动判断，不得以拟落地业务、工商经营范围或政策方向反向虚构事实。
4. **具体条目优先。** “符合新能源、数字经济、现代服务业”等宽泛描述无效，必须定位到目录名称、条目编号、条目名称和细化界定要点。
5. **目录召回不等于认定。** 检索脚本只召回候选；AI 必须比较企业事实、活动类型、业务对象、技术条件、规模阈值和排除条件后才能给出判断。
6. **相近可能有边界。** 相近可能必须存在实质重合，并明确缺失条件；不能把销售写成研发、使用写成生产、关联产业写成目录业务。
7. **准确性高于覆盖数量。** 没有合理候选时允许写“暂未发现明确匹配”，不得为了显得丰富制造擦边关系。
8. **检索未完成即阻断交付。** 目录文件缺失、版本不明、核心业务未覆盖或来源不可追溯时，不得生成正式报告。

## 三、目录范围与数据源

完整判断应覆盖现行海南自由贸易港鼓励类产业目录的三条来源路径：

1. 现行《产业结构调整指导目录》中的鼓励类产业；
2. 适用于外商投资企业时的现行《鼓励外商投资产业目录》；
3. 《海南自由贸易港鼓励类产业目录（2024年本）》中的海南新增鼓励类产业。

用户提供的《海南自由贸易港鼓励类产业目录（2024年本）界定指引》主要用于第三条路径的细化判断。实施时应保留原始工作簿，并生成 UTF-8 JSON 作为稳定运行数据源：

```text
references/catalogs/
├─ hainan-encouraged-industries-2024-guide.xlsx
├─ hainan-encouraged-industries-2024.json
└─ source-metadata.json
```

JSON 每条记录至少包含：

- `catalog_scope`：目录来源路径；
- `section_code`、`section_name`：行业门类；
- `item_no`、`item_title`：目录主条目；
- `detail_title`：细化目录；
- `definition`：行业描述及界定要点；
- `constraints`：规模、技术、资质、排除项等明确条件；
- `source_url`、`source_version`、`effective_date`：正式来源和版本；
- `source_hash`：本地原始文件校验值。

正式来源以国家发展改革委、海南省发展改革委等官方原文为准。用户提供的文件用于结构化取数和界定参考，不因文件名或上传渠道自动视为现行正式依据。

## 四、运行位置与数据流

新模块位于企业研究完成之后、三亚落地业务筛选和政策检索之前：

```text
主体确认
→ 企业事实台账
→ 主要业务及产品拆解
→ 鼓励类产业目录候选召回
→ 企业事实与界定要点比较
→ 目录匹配结果及校验
→ 三亚落地业务筛选
→ 政策检索与匹配
→ HTML / PDF / Word
```

报告位置固定在第二部分：

```text
（一）企业主体认定
（二）股权架构拆解
（三）主要业务及产品拆解
（四）海南自由贸易港鼓励类产业目录匹配
（五）行业地位及竞争位置
（六）上下游及国内外业务
```

目录匹配结果可以被后续政策条件引用，但本模块不得读取政策候选后再修改目录判断。

## 五、候选召回设计

新增只读检索工具 `scripts/search_industry_catalog.py`，对结构化目录执行候选召回。

输入包括：

- 业务名称；
- 产品或服务；
- 经营动作，如研发、生产、加工、运营、贸易、维修；
- 关键技术、资质、业务对象和规模条件；
- 企业是否为外商投资企业。

输出包括：

- 候选目录来源；
- 条目编号和名称；
- 细化条目与界定要点；
- 命中词及召回原因；
- 明确阈值和排除条件。

工具支持同义词和业务语义扩展，但只用于扩大候选召回，不能输出“符合”结论。AI 至少应比较：

1. 活动类型是否一致；
2. 产品或服务对象是否一致；
3. 技术、资质、规模和知识产权条件是否满足；
4. 条目中的限制类、淘汰类、配额等排除条件是否触发；
5. 企业证据证明的是现有业务还是未来设想。

每项业务默认保留最相关的候选，正式报告中“相近可能”最多展示 1—2 个，防止候选堆砌。

## 六、结构化数据契约

### 6.1 业务标识

为 `report-data.json` 的每个 `businesses` 项增加稳定且唯一的 `id`，格式为 `B01`、`B02` 等。目录判断通过 `business_id` 与业务一一对应，禁止依赖容易变化的业务名称文本关联。

### 6.2 顶层对象

在 `report-data.json` 增加必填对象 `encouraged_industry_assessment`：

```json
{
  "encouraged_industry_assessment": {
    "catalog_version": "海南自由贸易港鼓励类产业目录（2024年本）",
    "overall_judgment": "direct_match",
    "summary": "企业现有业务中存在可明确对应的鼓励类产业条目。",
    "catalogs_checked": [
      {
        "catalog_scope": "hainan_added_2024",
        "status": "checked",
        "source_id": "P01"
      },
      {
        "catalog_scope": "industrial_restructuring_current",
        "status": "checked",
        "source_id": "P02"
      },
      {
        "catalog_scope": "foreign_investment_current",
        "status": "not_applicable",
        "reason": "分析主体不是外商投资企业"
      }
    ],
    "business_assessments": [
      {
        "business_id": "B01",
        "business": "新型储能设备研发制造",
        "judgment": "direct_match",
        "matched_items": [
          {
            "catalog_scope": "hainan_added_2024",
            "catalog_item_no": "40",
            "catalog_item": "新型储能技术研发及设备制造",
            "detailed_item": "新型储能设备制造",
            "match_type": "direct"
          }
        ],
        "reason": "企业已公开披露从事电化学储能设备研发和制造，与条目活动类型和产品对象直接对应。",
        "enterprise_source_ids": ["E08"],
        "catalog_source_ids": ["P01"],
        "verification_needed": "需在正式申报时核实海南承接主体的实际业务材料。"
      }
    ]
  }
}
```

### 6.3 判断枚举

对外展示仅允许三种结果：

- `direct_match`：明确符合；
- `potential_match`：存在相近可能；
- `no_match`：暂未发现明确匹配。

内部另允许 `research_incomplete`，一旦出现必须阻断正式报告。

总体判断按以下规则计算：

- 任一业务为 `direct_match`，总体为 `direct_match`；
- 没有明确符合但至少一项为 `potential_match`，总体为 `potential_match_only`；
- 全部为 `no_match`，总体为 `no_match`；
- 任一业务或目录路径未完成，整体为 `research_incomplete` 并停止交付。

## 七、判断规则

### 7.1 明确符合

必须同时满足：

- 企业公开证据证明该业务已经存在；
- 企业活动类型与目录要求一致；
- 产品、服务或业务对象与条目一致；
- 已知事实未触发规模、技术、资质和排除条件冲突；
- 能引用企业来源和官方目录来源。

### 7.2 存在相近可能

必须同时满足：

- 至少有一个具体目录条目与企业业务存在实质重合；
- 已明确写出重合的活动、产品、服务或能力；
- 已明确写出缺少的关键事实或条件；
- 不使用“基本符合”“大概率符合”等容易被误解为资格结论的措辞。

典型情形包括：

- 企业销售相关产品，但目录要求研发或制造；
- 企业具备相关技术能力，但未发现已开展目录规定业务的证据；
- 业务方向一致，但目录要求的规模、资质或知识产权条件未核实；
- 企业存在上游或下游关联，但尚未证明其自身实施目录活动。

### 7.3 暂未发现明确匹配

在相关目录路径均完成检索、且不存在合理直接或相近条目时使用。必须简要说明已检查的业务范围和未匹配原因。不得通过选择一个关联度很低的条目来替代 `no_match`。

## 八、报告展示

HTML、PDF 和 Word 使用同一数据源，固定展示总体判断和逐业务表格：

| 企业业务 | 匹配结论 | 对应目录条目 | 判断依据 | 相近可能或待核事项 |
| --- | --- | --- | --- | --- |

展示要求：

- “明确符合”直接列出条目编号、名称和细化目录；
- “存在相近可能”列出最接近的 1—2 个条目及缺失条件；
- “暂未发现明确匹配”不得留空，须写清检索结论；
- 不展示内部检索日志和候选评分；
- 不使用“已经认定”“可以直接享受优惠”等政策资格措辞；
- 目录来源必须进入参考资料。现有 `P` 类来源过滤逻辑应同时保留被目录模块引用的官方来源。

## 九、校验与阻断规则

新增 `scripts/validate_encouraged_industry_assessment.py`，并在主流水线渲染前强制调用。

校验至少覆盖：

1. `encouraged_industry_assessment` 是否存在；
2. `businesses` 是否都有唯一 `id`；
3. 每个业务是否恰好有一条目录主判断；
4. 是否存在孤立或重复的 `business_id`；
5. 判断值和总体判断是否属于允许枚举且计算一致；
6. `direct_match` 是否至少有一项 `direct` 条目、企业证据和目录来源；
7. `potential_match` 是否有具体候选、重合理由和缺失条件；
8. `no_match` 是否没有伪造匹配项，并说明检索范围和原因；
9. 条目编号、名称和细化条目是否存在于结构化目录；
10. 目录版本、正式来源和校验值是否完整；
11. 外商投资目录是否仅在适用时启用，不适用时是否说明原因；
12. 是否出现“已认定”“保证享受”“自动符合”等越权表述；
13. 任一 `research_incomplete` 是否正确阻断渲染。

`scripts/validate_report_data.py`、`scripts/validate_text_quality.py` 和浏览器版式门禁继续执行。新模块不得绕过现有验证链。

## 十、异常处理

- **目录文件缺失或损坏：** 立即报错并停止交付；不得改用模型记忆补齐。
- **目录版本无法确认：** 标记 `research_incomplete`，停止交付。
- **企业业务证据不足：** 可判定 `potential_match` 或 `no_match`，不得判定 `direct_match`。
- **同一业务对应多个条目：** 保留真正独立的条目；同一条目的主条目和细化条目不得拆成重复结果。
- **目录条目存在阈值但公开信息缺失：** 只能判定 `potential_match`，并列明需补充的阈值证据。
- **官方目录与本地结构化数据不一致：** 以官方现行原文为准，阻断报告并要求更新本地数据和校验值。
- **政策分析引用目录结果：** 只能读取已校验结果，不得修改目录判断；政策资格仍按各自政策条件独立核验。

## 十二、测试设计

### 12.1 数据与检索测试

- 原始工作簿转换后条目数、行业门类和关键字段保持一致；
- 条目编号、主条目和细化条目无错误合并或错位；
- 中文、英文、数字、阈值和括号内容 UTF-8 往返无乱码；
- 典型关键词和同义词能够召回正确候选；
- 召回工具不直接生成资格结论。

### 12.2 判断校验测试

- 明确符合：真实业务和目录条目完整对应时通过；
- 相近可能：销售与研发、使用与生产、产业关联与实际经营等边界被正确降级；
- 暂未匹配：无合理候选时允许通过且不制造条目；
- 缺少任一核心业务判断时失败；
- 错误条目编号、错误目录版本、缺企业证据或缺官方来源时失败；
- `research_incomplete` 阻断流水线；
- 外商投资目录适用和不适用两种情形均覆盖。

### 12.3 报告与版式测试

- HTML、PDF、Word 三种输出内容同源；
- 模块始终出现，包括全部 `no_match` 的企业；
- 长条目名称和界定说明不造成表格横向越界、文本重叠或分页断裂；
- 参考资料保留目录模块使用的官方来源；
- 现有企业画像、财务、落地业务和政策匹配内容不回归。

### 12.4 回归样例

至少准备四类样例：

1. 有明确匹配的制造或研发企业；
2. 只有相近可能、但活动类型不完全一致的企业；
3. 全部业务均无明确匹配的企业；
4. 同时具有多个业务板块、外商投资属性或目录阈值条件的复杂企业。

全部测试纳入 `scripts/verify_skill.py --smoke` 和完整测试门禁。

## 十三、验收标准

实施完成必须同时满足：

1. 任意企业报告均固定出现目录匹配模块；
2. 每项核心业务均有明确、相近或未匹配结论；
3. 所有明确和相近结论均可追溯到企业证据与具体目录条目；
4. 不出现依靠行业大词、经营范围或政策方向作出的虚假匹配；
5. 缺目录、缺业务、缺来源或检索未完成时无法交付；
6. HTML、PDF、Word 内容一致且版式门禁通过；
7. 现有企业研究、政策检索和交付逻辑无回归；
8. 完整测试与跨 Agent 部署门禁全部通过。
