# 网页证据采集层设计

## 目标

为 `project-preliminary-assessment` 增加一个可选的、轻量的网页证据采集层，提升企业信息与海南、三亚正式政策的发现、提取、留痕和复核效率。采集层只负责取得可审计证据，不能改变现有“政策正式性、地域、现行状态和企业承接路径”判断结论。

## 范围与边界

- 采集仅面向企业官网、交易所/法定披露平台、政府及监管部门官网、海南省级和三亚市级主管部门官网等允许来源。
- 只采集公开可直接访问内容；不登录、不绕过验证码、不访问付费或受限系统、不保存 Cookie、账号或密钥。
- 第一阶段不部署 Firecrawl 服务端，也不复制其 AGPL-3.0 代码。实现自有、窄范围的采集逻辑；后续如引入 Firecrawl 适配器或代码，必须保留完整许可、版权及开源义务。
- 采集结果不能直接成为“可享受政策”。`validate_policy_scope.py` 及现有正式性、地域、有效状态和企业承接路径校验继续作为唯一政策准入门禁。
- 不改变现有企业检索规则、政策来源网站、Word/PDF/HTML 交付逻辑和报告模板。

## 工作流

```text
企业名称与拟落地业务
  -> 允许来源发现
  -> 抓取正文及 PDF/DOCX 附件链接
  -> 清洗为 Markdown、去重并记录证据元数据
  -> 企业研究/拟落地业务判断
  -> 现有政策范围与正式性校验
  -> 报告数据与 HTML/Word/PDF
```

## 新增组件

1. `references/source-registry.md`
   - 定义来源类别、允许域名、适用场景和优先级；企业、交易所、中央/海南/三亚官方来源可扩展登记。

2. `schemas/evidence.schema.json`
   - 定义 `evidence.json` 的最小结构与字段约束。

3. `scripts/collect_web_evidence.py`
   - 输入企业名称、检索主题和候选 URL。
   - 校验来源域名；抓取 HTML 正文；发现 PDF/DOCX 链接；以确定性方式清洗、限速、重试、去重。
   - 输出 `evidence.json` 及正文 Markdown 文件。

4. `scripts/evidence_collectors/`
   - 放置来源校验、HTML 正文提取、附件发现和去重等独立模块，避免把网络逻辑塞进报告脚本。

5. `scripts/validate_evidence.py`
   - 校验证据 JSON 的结构、允许来源、必填元数据、重复内容和抓取失败的显式记录。

## 证据数据要求

每条证据至少记录：

- `source_url`、`canonical_url`、页面标题、发布主体、来源类别、抓取时间；
- `content_path`、内容哈希、HTTP 状态、提取状态、错误信息（如有）；
- 明确的事实用途：企业主体、业务、财务、风险或政策线索；
- 附件 URL 与文件类型（如页面发现 PDF/DOCX）。

正文应保留为 UTF-8 Markdown。任何抓取失败必须可见，不得静默丢弃。

## 采集策略

- 只对已登记或本次显式批准的官方/权威域名采集。
- 默认按单页采集；同域附件发现为浅层、受数量限制的补充，不作全站爬取。
- 对同一规范化 URL 和同一正文哈希去重；记录重定向后的规范 URL。
- 采用短重试、限速和明确超时，失败后输出错误而不是无限重试。
- HTML 先提取正文；PDF/DOCX 保留链接与元数据，后续由现有文档提取流程处理。

## 与政策逻辑的接口

- 企业研究先判断真实业务和三亚承接路径；采集层仅为此提供事实证据。
- 政策检索仍由拟落地业务触发。采集到的新闻、规划、招商宣传只能作为线索，不能替代政策原文、实施细则、办理指南或当前申报通知。
- 政策进入报告前，仍须具备官方原文、现行状态、地域依据、适用条件、办理方式和企业承接路径。

## 验收与回归

1. 以飞科样例生成符合 schema 的企业/政策证据台账。
2. 非允许域名、缺失抓取状态、空正文、重复 URL/内容必须被验证器拒绝或明确标记。
3. 外省、非三亚适用地区的政策，即使被采集，也必须继续被现有政策范围校验排除。
4. 现有 25 项测试、HTML 报告流水线与 UTF-8 预检必须通过。
5. 输出不包含账号、Cookie、密钥或受限页面内容。

## 后续可选增强

在首期稳定后，才评估是否增加：JavaScript 渲染页面适配、Firecrawl 云 API 适配器、有限深度站内遍历或批量任务。每项增强都必须维持来源白名单、证据结构和现有政策门禁。
