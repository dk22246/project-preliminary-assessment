# 修复耗时超标与目录检索漂移 — 实施计划

> 基线日期：2026-09-27。目标：上市 ≤30 分钟、非上市 ≤15 分钟；目录检索不再漂移。

## 问题与堵点（已实证）

### 耗时（老板电器上市实测 36 分钟，超标）

| 阶段 | 耗时 | 性质 |
|---|---|---|
| 确认企业主体 | 9.8 分钟 | AI 搜索 |
| 政策发现 | 26 分钟 | AI 实时抓取 |
| 编译+校验+渲染 | ~13 秒 | 程序 |

程序侧已达标，慢在 AI 两段。三个堵点：

1. 政策抓取「串行 + 20s 超时 + 失败重试退避」，官方站点慢/失败即空转。
2. 缓存按 `run_id` 隔离，跨轮/新项目全量重抓；政府站多不支持 304 条件请求。
3. 主体确认无硬性快路径。

### 目录漂移（已复现）

检索「电子商务 跨境电商」误召回「服务外包」（definition 含"电子商务"四字被子串命中）。三层根因：

1. 检索用子串匹配，`definition` 全文被纳入召回依据。
2. 库 2860 条仅 176 条（海南目录）结构化，其余长文本区分度低。
3. 最终「明确符合/相近/无匹配」由 AI 自由判断，间歇漂移。

## 阶段一：治漂移

### 1.1 检索匹配精确化
- 文件：`scripts/search_industry_catalog.py`（`_rank`）
- 改法：召回命中只认 `item_title` + `detail_title`，`definition` 不再作为召回依据（保留给 `classify_catalog_entry` 判断活动类型/条件用）。
- 验收：「电子商务」不再召回「服务外包」；「油烟机/燃气灶」仍命中 #14。

### 1.2 锁定 AI 认定规则
- 文件：`references/encouraged-industry-assessment.md`
- 改法：写死「明确符合/相近可能/暂未发现」判定标准与 `detail_index` 选取规则。
- 验收：同输入多跑结果一致。

### 1.3（备选）库结构统一
- 文件：`complete-industry-catalog-library.json` + `build_industry_catalog_library.py`
- 仅在 1.1+1.2 不足时启动。

## 阶段二：治耗时

### 2.1 缓存跨轮复用
- 文件：`scripts/policy_cache.py`（`revalidate`）
- 改法：去掉 `round_id == run_id` 绑定，改为「同一 URL + 24 小时窗口 + sha256 一致」即复用；补首次抓取的 `revalidated_at` 字段。契合 SKILL.md「24 小时实时核验」硬规则。

### 2.2 抓取提速
- 文件：`scripts/discover_current_policies.py` + `scripts/ppa.py` 默认参数
- 改法：timeout 20→10s；同域名允许 2 并发；重试退避缩短。

### 2.3 主体确认快路径
- 文件：`SKILL.md` + `references/entity-resolution.md`
- 改法：写死「无歧义快速解析、有歧义才列 2-4 选项」，限定搜索轮次。

## 阶段三：验证与回归
- 老板电器（上市）+ 一个非上市企业各跑一遍，记录阶段耗时，确认达标。
- 跑 `tests/` 回归，确认门禁未破坏。
- 每阶段一个 git commit。

## 执行顺序
1.1 → 1.2 → 2.1 → 2.2 → 2.3 → 阶段三（1.3 挂起，视效果再定）。
